# SLSA Build L3 — Gap Analysis (roadmap, not a claim)

**Status of this document:** roadmap / scoping. It enumerates what SLSA **Build L3**
would require and the concrete deltas from the pipeline's **current Build L2**. It is
**not** an assertion that L3 is met.

**Current achieved level: SLSA Build L2.** This matches the honest banner in
`scripts/build-audit-document.py:58` ("SLSA Build L2 achieved — L3 is NOT claimed —
provenance generation is best-effort and not demonstrably isolated from the build
job") and the claims register at `scripts/build-audit-document.py:1602`. Every
auditor-facing string in the repo reads "SLSA Build L2" consistently after T-44.

**Spec mapping:** evidence-pack-specification §3 "Build provenance" row ("SLSA Build
L2+ (L3 target)"); struktura A/§5 row C.12; blueprint K5
([COMPANY-AUDIT-2026-06-09.md](../../COMPANY-AUDIT-2026-06-09.md) §3.3). Gap-register
entry: [`docs/compliance/gap-register.md`](compliance/gap-register.md) G-09.

## 1. What "Build L3" means (slsa.dev v1.0)

The SLSA v1.0 Build track has three levels. L3 = "all of L2, plus a **hardened**
build platform." Two named requirements are **L3-only** — both are properties the
build *platform* must provide, not the build *config*:

| Requirement (slsa.dev v1.0) | Applies to | Plain meaning |
|---|---|---|
| Provenance Exists | L1, L2, L3 | Provenance generated, identifies output by digest. |
| Provenance is Authentic | L2, L3 | Provenance is signed; consumers can validate authenticity. |
| **Provenance is Unforgeable** | **L3 only** | Provenance is "strongly resistant to forgery by tenants" — secret signing material is stored in a secure system **inaccessible to user-defined build steps**. |
| Isolation strength: Hosted | L1, L2, L3 | Build runs on a hosted platform (not a workstation). |
| **Isolation strength: Isolated** | **L3 only** | Build steps run in an isolated environment "free of unintended external influence" — one run cannot influence another (no cache poisoning, no persisted environment, no access to platform secrets). |

Sources:
[slsa.dev/spec/v1.0/levels](https://slsa.dev/spec/v1.0/levels),
[slsa.dev/spec/v1.0/requirements](https://slsa.dev/spec/v1.0/requirements),
[slsa.dev/spec/v1.0/verifying-systems](https://slsa.dev/spec/v1.0/verifying-systems).

The pipeline **already meets** Provenance Exists, Provenance is Authentic, and
Hosted. The gap to L3 is exactly the two L3-only requirements:
**Unforgeable** and **Isolated**.

## 3. The two L3 gaps and the concrete change for each

### Gap A — "Provenance is Unforgeable" (signing key inaccessible to build steps)

**Why we are not L3 here today.** The fallback provenance is generated by
`scripts/generate-provenance.sh` *inside the same job* that builds/handles the image
(`sign-and-attest.yml:88-100`). Keyless cosign signing uses the job's OIDC token,
which the user-defined steps in that job can read (it is granted at job scope via
`id-token: write`). A malicious or compromised build step in the same job could, in
principle, mint provenance or signatures using that token — provenance is therefore
**not demonstrably unforgeable by the tenant**. This is the exact kernel called out
in `scripts/build-audit-document.py:58` and blueprint §6.4-D.

**Concrete change to meet it:**
1. Make `actions/attest-build-provenance` (`sign-and-attest.yml:79-86`) the
   **primary, non-degradable** path rather than a `continue-on-error` fallback.
   That action generates and signs provenance from GitHub's control plane, so the
   signing identity is not exposed to user build steps. (Requires the repo to be on
   a plan/visibility where the native attestation API is available — today it is
   `continue-on-error` precisely because it is unavailable for private repos on
   personal accounts, `sign-and-attest.yml:81`.)
2. Alternatively, adopt the
   [slsa-framework/slsa-github-generator](https://github.com/slsa-framework/slsa-github-generator)
   reusable workflow, which runs provenance generation in a **separate, trusted job**
   the calling workflow cannot tamper with, and keeps the signing identity out of
   the build job. Retire the in-job `generate-provenance.sh` fallback as the
   authoritative source once a non-falsifiable path is the default.
3. Until then, keep `generate-provenance.sh` only as an explicitly-labelled
   best-effort fallback (its output is honest L2, not L3).

### Gap B — "Isolated" build environment (no cross-run influence)

**Why we are not L3 here today.** L3 requires the *platform* to guarantee that one
run cannot influence another (cache poisoning, persisted environment, access to
platform secrets). GitHub-hosted ephemeral runners provide fresh VMs per job, which
is strong — but the pipeline does not currently use a build platform that **attests**
this isolation in a way a verifier can pin, nor does it constrain shared caches
(`actions/cache`, Docker layer caches) to prevent cross-run poisoning. We do not
publish an isolation guarantee a consumer can verify, so the **Isolated** requirement
is not demonstrably met.

**Concrete change to meet it:**
1. Build on a platform whose isolation is part of its SLSA verifiability — the
   `actions/attest-build-provenance` / `slsa-github-generator` path on
   GitHub-hosted runners is the documented route to a verifier being able to trust
   GitHub Actions' run isolation (see
   [slsa.dev/spec/v1.0/verifying-systems](https://slsa.dev/spec/v1.0/verifying-systems)).
2. Eliminate or scope build caches so a prior run cannot inject inputs into a later
   run (no shared mutable cache keyed on attacker-controllable input across runs).
3. Confirm no self-hosted/long-lived runners are introduced for the build/sign jobs
   (all are `ubuntu-latest` today — keep it that way; a self-hosted runner would
   *regress* isolation).

## 4. Supporting delta — builder identity (already closed, kept for completeness)

L3 verification relies on a verifier being able to **pin the builder identity**.
`builder.id` is now the ref-pinned `${GITHUB_WORKFLOW_REF}` URI and matches the
cosign keyless certificate subject used in CI (T-50, `generate-provenance.sh:18-25`).
This was a prerequisite, not the gap itself; it is **done**. The remaining work is
Gaps A and B above.

---

## 5. Summary

| L3 requirement | Status today | Change required |
|---|---|---|
| Provenance Exists | MET (L1+) | — |
| Provenance is Authentic | MET (L2) | — |
| Isolation: Hosted | MET (L2) | — |
| **Provenance is Unforgeable** | **NOT MET** | Native/reusable-workflow provenance signed outside the build job; signing identity not readable by user steps (Gap A). |
| **Isolation: Isolated** | **NOT MET** | Verifiable platform isolation + no cross-run cache poisoning; no self-hosted runners (Gap B). |

**The pipeline is SLSA Build L2 today.** L3 is a roadmap item, scoped above, not a
current claim.
